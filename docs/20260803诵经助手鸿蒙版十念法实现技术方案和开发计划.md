## 2. 目标

在 gongke_harmony 的「电子木鱼 / 念佛菩萨圣号」页面（`NianShengHaoPage`）中增加与 Swift 功课助手同类的「播放模式」和「管理十念法」能力：

1. **普通模式**：继续播放现有的 `mp3/muyu.wav`。
2. **印光大师推荐十念法**：默认音序 `B B B｜C C C｜A A A A`。
3. **防昏沉十念法**：默认音序 `B C｜B C｜B C｜A A A A`。
4. 用户可以修改两个内置十念法的十声音序，并恢复内置默认值。
5. 用户可以创建、修改、试听、选择和删除自定义十念法。
6. 每个十念法固定 10 声，每一声只能是 A（低音）/ B（中音）/ C（高音）之一。

正式播放时，每敲一声推进一个声位；第 10 声后回到第 1 声。普通模式不参与十声循环，始终播放原木鱼音频。

建立「稳定模式 ID + 十声音序 + 全局模式库」，以后新增预置十念法时不需要修改播放状态机。

## 3. 本次范围

### 3.1 包含

- 在 `NianShengHaoPage` 的时间间隔与开始按钮之间，增加「播放模式」区域：模式 Picker + 当前音序说明 + 「管理十念法」入口。
- 普通模式不可编辑、不可删除。
- 两个内置模式可调整音序、可恢复默认、不可改名、不可删除。
- 自定义模式可新建、改名、编辑音序和删除（删除前必须选替代模式）。
- 编辑器支持未保存草稿试听，默认试听 20 声（两个完整循环）。
- 播放模式按「功课类型 `gongketype` + 功课名称 `name`」保存；同类同名功课跨日期复用设置。
- 正式功课开始时取得模式值类型快照，本轮播放不受管理页后续修改影响。
- 暂停、完成、离开页面时重置到十念法第 1 声。
- 普通 / A / B / C 音频预加载、互斥播放和资源缺失降级。
- 非法设置、未知模式 ID、损坏的持久化数据安全回退到普通模式。

### 3.2 不包含

- 不增加语音报数或屏幕上的 1～10 动画。
- 不允许上传 / 录制 / 导入自定义音频。
- 不支持 A / B / C 之外的音色。
- 不支持任意长度音序，本期严格固定为 10 声。
- 不为各声位分别设置音量、速度、时间间隔或第 10 声后的额外停顿。
- 不改变 `GongKeItem.cnt`、完成状态、功课统计的统计口径（仅复用既有完成标记）。
- 不新增 `gongketype`、不改动 Drift 表结构（十念法配置写入轻量 KV，不写每日 `GongKeItem`）。
- 不在本期实现云端同步、导入导出或跨设备共享十念法。

## 4. gongke_harmony 现状分析

### 4.1 集成目标页：`lib/view/gongke/nianshenghao.dart`

当前承担「电子木鱼」页面，关键事实（已读源码确认）：

- `AppBar` 标题为「电子木鱼」，通过 `ModalRoute` 参数接收 `gongkeitem`（类型为 `GongKeItemData`）。
- 本地状态：`interval`（默认 1.0 秒，滑块 0.5~3.0s，但**未持久化**）、`currentCount`、`isRunning`。
- `start()`：`await AudioTools.playLocalAssetAndWait('mp3/yinqing.wav')` 先敲引磬 → 用 `Timer.periodic` 每隔 `interval` 自动播放 `mp3/muyu.wav` 并 `currentCount++` → 到达 `cnt` 后 `_finishSequence()` 再敲结束引磬并 `WakelockTools.disable()`。
- 已有**竞态防护雏形**：引磬 `await` 之后检查 `if (!mounted || !isRunning) return;`。本方案会把「引磬延迟 + 状态机」正式抽成可取消控制器，彻底消除退出后回放竞态。
- **未持久化完成状态**：当前 `nianshenghao` 导航只传 `{'gongkeitem': item}`，不回写 `isComplete`。为与 Swift 版一致，本方案在十念法正式完成一轮时，调用 `globalDB.managers.gongKeItem` 将对应项 `isComplete` 置 `true`（仿 `nianzhou.dart` 的 `_updateCountBeforeExit`）。

### 4.2 音频能力（已就绪，零改造即可复用）

- `lib/comm/audio_tools.dart` 的 `AudioTools` 基于 `audioplayers`（OHOS 专用 fork，来自 gitee，已在 `pubspec.yaml:60-63` 声明并在 `ohos` 端注册 `AudioplayersPlugin`）。

### 4.3 震动 / 屏幕常亮 / 传感器（已就绪）

### 4.4 持久化能力

## 6. 播放会话规则

| 场景 | 十念法位置处理 |
| --- | --- |
| 第一次开始功课 | 读取所选模式快照，从第 1 声开始 |
| 正常下一声 | 实际播放后位置 +1，第 10 声后回到第 1 声 |
| 点击「暂停 / 结束」停止 | 停止木鱼并把位置重置为第 1 声 |
| 再次开始 | 使用本次开始时重新读取的模式，从第 1 声开始 |
| 完成功课 | 重置位置并清理会话快照，标记 `isComplete` |
| 离开页面 | 取消定时器、取消待执行的延迟引磬、停止木鱼并清理快照 |
| 新一次设置页 / 编辑器试听 | 从第 1 声开始 |
| 停止试听后重播 | 从第 1 声开始 |
| 音频中断 | 停止试听或正式播放，不推进未实际播放的声位 |
| 普通模式 | 始终播放 `mp3/muyu.wav`，不显示循环位置 |

模式快照规则：

- 点击开始时由仓库解析一次模式，保存到 `activeRhythmPattern`（值类型）。
- 每个定时器事件只读取这个快照，不每声查 KV。
- 管理页对同一模式的修改不影响已经开始的一轮。
- 停止后再次开始会读取最新保存版本。
- 这也消除当前「引磬延迟后，退出或停止仍可能回放」的竞态：延迟启动使用可取消的 `Timer` / 会话令牌。

## 7. 领域模型设计（Dart）

新增 `lib/model/muyu_rhythm_pattern.dart`，纯值类型，可单元测试：

```dart
enum MuyuSoundVariant {
  regular,
  a, // 低音木鱼
  b, // 中音木鱼
  c, // 高音木鱼
  ;

  static const List<MuyuSoundVariant> editableCases = [a, b, c];

  /// 对应音频资源（regular 用现有 muyu.wav，A/B/C 用新增音频）
  String get asset {
    switch (this) {
      case MuyuSoundVariant.regular:
        return 'mp3/muyu.wav';
      case MuyuSoundVariant.a:
        return 'mp3/muyu_a.mp3';
      case MuyuSoundVariant.b:
        return 'mp3/muyu_b.mp3';
      case MuyuSoundVariant.c:
        return 'mp3/muyu_c.mp3';
    }
  }
}

enum MuyuRhythmPatternSource {
  regular,
  builtIn,        // 可被用户覆盖
  custom,
}

class MuyuRhythmPattern {
  final String id;
  final String displayName;
  final List<MuyuSoundVariant> sequence;
  final MuyuRhythmPatternSource source;
  final bool isOverridden; // 内置被改过

  const MuyuRhythmPattern({
    required this.id,
    required this.displayName,
    required this.sequence,
    required this.source,
    this.isOverridden = false,
  });

  /// 取第 index 声（0 基）的音色，按序列长度循环；空序列回退 regular
  MuyuSoundVariant variantForZeroBasedStrikeIndex(int index) {
    if (sequence.isEmpty || index < 0) return MuyuSoundVariant.regular;
    return sequence[index % sequence.length];
  }

  /// 音序说明，如 "B B B｜C C C｜A A A A"（由 sequence 计算，不单独存）
  String get groupedDescription {
    if (source == MuyuRhythmPatternSource.regular) return '使用普通木鱼声';
    final names = sequence.map((v) => v.name.toUpperCase()).join(' ');
    final parts = [names.substring(0, 5), names.substring(6, 11)];
    return parts.join('｜');
  }
}
```

## 8. 持久化设计（shared_preferences 单键 JSON 快照）

### 8.1 推荐方案：版本化 JSON 快照

数据量很小（播放偏好，非功课历史），推荐新增一个统一快照，存为 `shared_preferences` 中的单一字符串键：

- 键名：`gongke.muyuRhythmPreferences`
- 结构（Dart 类 + `toJson / fromJson`）：

```dart
class MuyuRhythmPreferencesSnapshot {
  final int schemaVersion;
  final List<StoredMuyuRhythmDefinition> builtInOverrides; // 用户改过的内置音序
  final List<StoredMuyuRhythmDefinition> customPatterns;   // 自定义十念法
  final List<MuyuRhythmSelection> selections;              // 各功课选择的模式
}

class StoredMuyuRhythmDefinition {
  final String id;
  final String name;
  final List<String> sequence; // ['a','b','c',...] 仅 a/b/c
  final int sortOrder;
  final int createdAt; // epoch ms
  final int updatedAt;
}

class MuyuRhythmSelection {
  final String gongKeType;
  final String gongKeName;
  final String patternID;
}
```

- 整个快照编码为 JSON 字符串，写入单一键。
- **选择记录用两个独立字段 `gongKeType` + `gongKeName`**，不再拼接 `"类型|名称"`，从结构上避免名称含分隔符造成冲突（Swift 0802 文档 §8.1 同类修正）。
- 自定义模式 ID 使用 `user.<uuid>`。

推荐理由（镜像 Swift 0802 文档 §8）：

- 与现有木鱼间隔一样，设置独立于每日 `GongKeItem`，不污染历史数据。
- 不修改已发布 App 的 Drift Schema，不承担迁移风险。
- 数据很小，最多 50 个模式和少量选择记录，完整 JSON 快照足够。
- 删除模式与批量替换引用可在内存一次完成，再整体写入，不留半完成态。
- `schemaVersion` 为将来扩展提供入口。

### 8.2 为什么不写入 `GongKeItem`

- `GongKeItem` 是每日记录，不是播放设置实体；同一发愿会为每天复制一条记录，保存模式会产生大量重复值。
- 修改发愿时未来记录会被删除重建，设置易丢失。
- 删除自定义模式时要更新大量历史/未来记录，成本与语义都不合理。

### 8.3 读取、升级与损坏处理

1. 键不存在：创建空快照，展示三个代码内置模式，所有选择默认普通模式。
2. `schemaVersion == 1`：正常解析。
3. 未来版本高于当前支持版本：不覆盖原数据，记录诊断并只读回退内置模式。
4. 单条自定义定义非法：忽略该条，其他合法模式继续可用。
5. 整体数据无法解码：保留原始字符串，不自动覆盖；UI 回退内置模式并显示一次可理解错误提示。
6. 未知选择 ID：运行时回退普通模式；下次用户主动选择时写入有效 ID。
7. 每次写入前先完成全部校验，编码成功后才调用 `saveStringValue`。

## 10. 音频设计

### 10.1 新增 A / B / C 三种木鱼音（必需）

gongke_harmony 当前 `assets/mp3/` 只有 `muyu.wav`（普通）、`yinqing.wav/mp3`（引磬）、`muyu_normal*.mp3`（连续背景音，本期不用）。**十念法需要三种音高区分的木鱼音**：

- 来源：从 Swift 原版 `GongKeAssistant/Resources/` 的 `muyu_a.m4a` / `muyu_b.m4a` / `muyu_c.m4a`（其源头是 NianFoAssistant）复制。
- 格式：建议转为 **`.mp3` 或 `.wav`**（这两种格式已在 OHOS 端被 `audioplayers_ohos` 实际使用并验证，`.m4a` 在 OHOS 上兼容性不确定，不冒险）。放入 `assets/mp3/`，命名 `muyu_a.mp3` / `muyu_b.mp3` / `muyu_c.mp3`（`pubspec.yaml` 已声明 `assets/mp3/`，新增文件自动包含，无需改 pubspec）。
- **音高校验（重要，沿用 Swift 0802 文档 §4.3 警告）**：复制后用文件哈希核对来源，再以真机/模拟器逐音试听确认 A=低音、B=中音、C=高音。不能仅凭旧文档判断，因为源项目音频曾调整过。

### 10.2 独立十念法音频服务

新增 `lib/comm/muyu_rhythm_audio_player.dart`，降低对现有 `AudioTools`、引磬播放的回归风险：

- 内部维护 4 个 `AudioPlayer`（按 `playerId` 区分：regular / a / b / c），初始化时各自 `setSource(AssetSource(...))` 预加载。
- 播放规则：
  1. 播放某音色前，停止并归零其他 3 个木鱼播放器，避免不同音高重叠。
  2. 当前播放器每次从 0 开始。
  3. 资源缺失时按 `C→B→A→普通`、`B→A→普通`、`A→普通` 降级。
  4. 加载/播放失败记录错误但不崩溃。
- `stopMuyu()` 停止并归零全部木鱼播放器。
- 监听音频中断（OHOS 上可通过 `audioplayers` 的 `onPlayerStateChanged` / 系统音频焦点回调；若 OHOS 端无现成中断事件，至少保证「停止/退出时显式 stop」即可，中断处理标记为可选增强）。

现有 `AudioTools` 继续负责引磬（`yinqing.wav`）及将来其他长/短音频，本期不改其公开行为。

### 10.3 音频互斥

- 开始播放引磬前停止十念法木鱼。
- 第一声木鱼开始前，引磬应已结束或被明确停止。
- 点击停止或离开页面时，同时停止十念法木鱼、取消定时器与延迟引磬任务。
- 功课完成播放结束引磬前先停止木鱼，避免尾音与引磬重叠。

## 12. 正式播放会话控制器

为避免继续把模式、延迟引磬、计数逻辑堆在 `NianShengHaoPage` 里，新增 `lib/comm/nianfo_muyu_session_controller.dart`：

```dart
enum NianFoMuyuState { idle, leadingChime, playing, completed }

class NianFoMuyuSessionController {
  NianFoMuyuState state = NianFoMuyuState.idle;
  int remainingCount = 0;

  MuyuRhythmPattern? activePattern;
  int strikeIndex = 0;            // 独立声位索引，不绑定剩余次数
  Timer? _leadingChimeTimer;     // 可取消延迟引磬
  Timer? _beatTimer;             // 正式节拍定时器

  void start({required MuyuRhythmPattern pattern, required int totalCount});
  void handleBeat();             // 每拍：取音色→播放→推进索引→remainingCount-1
  void pause();                  // 用户停止：取消定时器、停止音频、索引归零
  void dispose();                // 离开页面：彻底清理
}
```

状态：`idle → leadingChime → playing → completed`，`leadingChime` 可经用户停止回到 `idle`。

职责（镜像 Swift 0802 文档 §12）：

- 开始时取得模式快照和总次数（从 `muyuRhythmStore` 解析一次）。
- 播放引磬期间用可取消 `Timer` 防止重复点击创建多个延迟任务。
- 每个有效节拍事件播放当前声位、推进 `strikeIndex`、减少 `remainingCount`。
- 最后一声完成后，由页面执行 `globalDB` 更新 `isComplete`（仿 `nianzhou.dart`）。
- 停止、完成、退出、中断时统一清理定时器、延迟任务、音频和索引。
- `handleBeat` 全部交给控制器判断状态，页面只负责渲染与保存完成状态。

> 实现时可继续使用 `Timer.periodic` 驱动正式敲击（如同现有 `nianshenghao.dart`），但所有事件先交控制器判断状态；至少也要独立维护 `activePattern`、`strikeIndex` 和可取消延迟任务，**不能把音序推进绑定到 `remainingCount`**（非 10 倍数时首声会错）。

## 18. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 直接给每日 `GongKeItem` 加模式字段 | 重复数据、未来记录重建丢设置、引入 Drift 迁移 | 使用 shared_preferences 版本化 JSON 快照 |

| KV 数据损坏 | 模式库无法读取 | 版本号、逐条校验、保留原串、只读安全回退 |

## 20. 推荐实施结论

gongke_harmony 应采用：

```text
内置模板
  + shared_preferences 中的内置覆盖
  + shared_preferences 中的自定义模式
  + 按 gongketype / name 保存的模式选择
  + 正式播放会话快照
  + 独立预加载四音色音频服务
```

这套方案保留 Swift 功课助手已经验证过的产品体验和领域算法，同时适配 gongke_harmony「每日功课记录 + 全局播放偏好」的数据结构：不修改 Drift Schema、不污染每日历史数据、不改变现有 `AudioTools` 引磬职责，并为后续增加其他固定十声模式保留扩展空间。
