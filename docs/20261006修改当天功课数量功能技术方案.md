# 修改当天功课数量功能 — 技术方案与开发计划

> 状态：**已开发完成**（2026-10-06 评审通过并实施，待真机验证）
> 日期：2026-10-06

## 评审结论（2026-10-06 杨哥拍板）

1. **开关默认值**：默认「关」。
2. **右滑方向**：startActionPane（手指向右滑露左侧按钮，同主页"编辑"）。
3. **日期限制**：跟随现有规则，仅今天/昨天可编辑。
4. **改小数量**：只要修改了计划遍数，状态重置为未完成，已完成遍数（curCnt）重置为 0（不区分改大改小）。

## 一、需求分析

### 1.1 需求描述
1. **系统设置页**新增开关：「是否允许修改当天功课数量」。
2. **查看当天功课页**（功课设置页，`gongke_setting.dart`）：开关开启时，功课条目支持右滑呼出「修改数量」按钮，点击打开页面修改该条功课的目标数量（`cnt`）并保存；开关关闭时保持现状（无右滑操作）。

### 1.2 现状梳理
| 项 | 现状 |
|---|---|
| 当天功课页 | `lib/view/gongke/gongke_setting.dart`，功课条目 `_buildTaskRow` 为普通 `InkWell`，**无 Slidable** |
| 功课数量 | `GongKeItem.cnt`（目标遍数）+ `curCnt`（当前完成遍数），字段已存在，**数据库不用改** |
| 系统设置页 | `lib/view/setting/setting_page.dart`，现有帮助中心/反馈/界面一览/关于，**无开关类设置** |
| KV 存储 | `lib/comm/shared_preferences.dart` 已有 `saveBoolValue/getBoolValue`，直接复用 |
| 编辑权限 | 现有 `_canEdit` 规则：仅今天/昨天可编辑（完成开关、进入功课详情都受此限制） |

### 1.3 用户价值
发愿设定的功课数量是长期计划，但当天可能临时加量/减量（如身体不适减量、精进加量）。此功能允许"当天实际数量"与"发愿计划数量"不一致，且默认关闭，不改变老用户习惯。

## 二、技术方案设计

### 2.1 开关存储
- KV key：`gongke.allowModifyTodayCnt`（对齐现有 `gongke.todayTip.mode` 命名风格）
- 默认值：**关**（关闭=现状）
- 读写：复用 `saveBoolValue / getBoolValue`

### 2.2 设置页改动（setting_page.dart）
在「帮助中心」section 上方新增「功能设置」section，内放一个 `SwitchListTile`（EDS 风格卡片内），标题「允许修改当天功课数量」，副标题说明用途。开关状态 `initState` 异步加载，切换即保存。

### 2.3 当天功课页改动（gongke_setting.dart）
`_buildTaskRow` 外层包 `Slidable`：
- 开关开 → `startActionPane` 含一个 `SlidableAction`（图标 `Icons.exposure`，标签「修改数量」，蓝色），点击跳转修改页
- 开关关 → 不渲染 `Slidable`，直接返回原 `InkWell`（保持现状，右滑无任何反应）
- 页面进入时（`didChangeDependencies`）读取开关状态存入本地变量
- 方案采用 **startActionPane（手指向右滑、露出左侧按钮）**，与主页发愿条目「编辑」操作方向一致。⚠️ 若你指的是"从右边缘往左滑、露出右侧按钮"（endActionPane），文档评审时说明，改一个参数即可

### 2.4 新页面：修改功课数量（新文件）
`lib/view/gongke/modify_gongke_cnt.dart`，路由 `/GongKe/GongKeSetting/modifyCnt`（对齐现有 `/GongKe/GongKeSetting/nianzhou` 命名）：
- StatefulWidget；`TextEditingController` 为 State 成员，在 `State.dispose()` 中释放（**遵守 2026-08-22 踩坑结论：不用 showDialog + 立即 dispose 的模式**）
- UI：功课名称展示（只读）+ 数字输入框（纯数字键盘）+ 「-10 / -1 / +1 / +10」快捷按钮 + 重置提示 + 「保存」
- 校验：正整数（digitsOnly 输入过滤 + 保存按钮禁用 + errorText 提示）
- 保存逻辑（按评审结论）：
  1. **仅当新数量 ≠ 原数量时写库**：`update gongKeItem.cnt = 新数量, curCnt = 0, isComplete = false`
  2. 调 `syncTaskAndCalendarCards()` 同步桌面卡片（今日功课卡片显示数量）
  3. 调 `onUpdated()` 回调（功课设置页传入：`updateCallback()` 刷新主页 + `_refreshAllData()` 刷新自身）
  4. `Navigator.pop(context, true)` 返回

### 2.5 数据边界（按评审结论）
- 修改数量时：`cnt` 更新为新的目标数量，**`curCnt` 重置 0、`isComplete` 重置 false**（改大改小一视同仁，重新计数）
- 仅当新数量 ≠ 原数量时写库（原值保存不产生副作用）
- 修改数量**跟随现有 `_canEdit` 规则**（仅今天/昨天可操作），保持页面权限语义一致
- 路由注册：`main.dart` 的 `routes` 加一条
